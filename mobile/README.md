# Rituva — Android/iOS app (Flutter)

A native client for the Rituva API, on the approved design. Shares the exact same
backend as the PWA — every nutrient number comes from the Knowledge DB.

> This folder holds the Dart **source** (`lib/` + `assets/`). The native `android/`,
> `ios/`, etc. scaffolding is generated by Flutter (and by CI) — see below.

## Works with no backend (offline-first)

The app ships with a bundled demo (`assets/demo.json`, built by the real engine) and
falls back to it whenever no server is reachable — so a fresh install (or a Simulator
with nothing running) opens straight into a working plan with an **"offline demo"**
banner, instead of an error. Point it at a live backend any time in **Profile → Server**.

## Run on iOS Simulator (macOS + Xcode)

```bash
flutter create .        # generates ios/ around the existing lib/ (first time only)
flutter pub get
flutter run             # with an iOS Simulator booted
```

- The default API base on iOS is `http://localhost:8000` (Simulator → host localhost).
- You don't need a backend to explore the UI — the offline demo covers Today/Plan/Health.
- To connect a **local** backend over plain HTTP, iOS App Transport Security must allow
  cleartext: in `ios/Runner/Info.plist` add
  ```xml
  <key>NSAppTransportSecurity</key>
  <dict><key>NSAllowsArbitraryLoads</key><true/></dict>
  ```
  (CI injects this automatically; do it locally only if you want a live HTTP server.)

## Run on Android emulator / device

```bash
uvicorn rituva.api:app --host 0.0.0.0 --port 8000   # optional — only for a live backend
flutter create .        # generates android/ (first time only)
flutter pub get
flutter run
```

- Default API base on Android is `http://10.0.2.2:8000` (emulator → host localhost).
- For a physical device, open **Profile → Server** and enter your PC's LAN IP
  (e.g. `http://192.168.1.5:8000`), or bake a URL at build time with
  `--dart-define=RITUVA_API=https://your-host`.
- Android cleartext HTTP + the `INTERNET` permission are injected by CI; for a local
  Android build add `android:usesCleartextTraffic="true"` to the `<application>` tag and
  `<uses-permission android:name="android.permission.INTERNET"/>` to the manifest.

## Prebuilt downloads (CI)

- **Android APK** — every push to `main` refreshes the rolling `latest` release
  (`.github/workflows/build-apk.yml`). Download and install directly.
- **iOS** — `.github/workflows/build-ios.yml` verifies the iOS build on macOS
  (unsigned). Running on a real iPhone needs your own Apple signing; the Simulator flow
  above is the easy path.

## What's implemented

- **Today** — calorie ring + macro bars + cited guideline rule + meal cards; tap a
  meal to see iso-nutrient **swap** alternatives (per-ingredient DB numbers).
- **Plan** — the week (DQS per day); **tap any day** to see its meals; **Grocery**
  bottom sheet (categorized, household-scaled).
- **Health** — targets (BMI/kcal/protein + citations), conditions, and **never/dislike
  memory** (add/remove) that reshapes the plan.
- **Profile** — household member switch, **Server URL** setting, engine/provenance.

## Structure

```
lib/
  main.dart          # app + nav shell + state load + Profile (Server URL) + offline banner
  theme.dart         # approved Rituva color tokens + humanize()/slotLabel() helpers
  api.dart           # RituvaApi HTTP client — offline-first, platform-aware base URL
  screens/
    today.dart       # Today (ring, macros, meals, swap sheet)
    plan.dart        # Week + day-detail sheet + grocery sheet
    health.dart      # targets + conditions + memory
assets/
  demo.json          # engine-built offline demo bundle (DB-grounded)
  icon/              # My Plate ring launcher-icon sources
```
