# ---------------------------------------------------------------------------
# Rituva dependencies
#
# The deterministic CORE (rituva.targets / nutrition / planner / knowledge) and
# the CLI run on the Python STANDARD LIBRARY ALONE — no install required:
#     python -m rituva.cli --member ankit --days 7
#
# The packages below enable the advanced stack described in PRD §12.3. Each is
# optional; the code degrades gracefully when it is absent (e.g. LangGraph -> plain
# sequential runner; no LLM key -> deterministic no-LLM planner).
# ---------------------------------------------------------------------------
pydantic>=2.0        # typed API models (PRD §12.5)
fastapi>=0.110       # REST API layer (PRD §12.5)
uvicorn>=0.29        # ASGI server
langgraph>=0.2       # stateful orchestration graph (PRD §9.7) — optional
openpyxl>=3.1        # .xlsx export/import for Excel parity (PRD §11.3)
fpdf2>=2.7           # PDF export of the plan (/plans/{id}/export.pdf)
python-dotenv>=1.0   # load a local .env (LLM keys etc.) — optional
pytest>=8.0          # test runner (tests also run standalone without it)

# LLM providers are reached over their OpenAI-compatible HTTP endpoints using the
# standard library (urllib) — no vendor SDK needed. Configure a key on Settings:
#   NVIDIA build.nvidia.com  ->  https://integrate.api.nvidia.com/v1  (PRD §10.5)
#   Local models             ->  Ollama (https://ollama.com)
# Optional Postgres + pgvector backend (PRD §12.3): pip install "psycopg[binary]"
#   Set RITUVA_DB=postgresql://user:pw@host/db and store.py persists to Postgres while
#   the hybrid retriever's dense channel moves to pgvector (rituva/pgvector_index.py).
#   `docker compose up -d` brings up Postgres 16 + pgvector locally. SQLite + in-memory
#   retrieval remain the zero-dependency default; the standalone mobile app uses neither.
